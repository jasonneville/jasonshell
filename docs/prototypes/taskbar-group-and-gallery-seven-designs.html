One app. Many windows. One clear family.

More than a number
in the corner.

Seven paired treatments for a grouped bottom-bar tile and the window gallery it belongs to. Depth, seams, rhythms, spines: make “more than one window” part of the tile’s shape, then carry that idea upward into the gallery.

Static illustrations — no shell actions work. All seven galleries are shown open by default; no hovering needed. Thumbnails are drawn samples, not live captures. Close marks and window states are illustrative. Only document links and scene scrolling are functional.

Pale blue marks the active window; text also identifies state. 2, 3, 4 and 6-window groups shown. At narrow widths, focus a scene and use arrow keys to scroll. Current runtime gallery is a compact title strip with separate previews; these combined thumbnail galleries are proposals, not shipped behavior.

01 / Layered folio

Favorite · safest upgrade

Two fine backplates turn a tile into a small stack. The gallery opens that stack into equally weighted window cards, under one shared app heading.

Why: Familiar shell geometry, improved group recognition even before reading the count.

Trade-off: Backplates indicate plurality, not exact quantity; still needs the number.

02 / Twin seam

Purpose-built pair

An integrated two-window compartment replaces the corner badge. Above it, a book-like gallery puts two windows side by side, separated by one deliberate seam.

Why: Exceptionally clear for the most common small group: two windows.

Trade-off: Beyond two, replace pictograms with an inline count and extend the gallery; this exact pair layout does not scale.

03 / Window ribbon

Favorite · compact rhythm

Three slim window marks form the tile’s lower rhythm. The gallery repeats it as a horizontal, image-first thumbnail strip with captions close to the bar.

Why: Strong correspondence between tile and gallery with almost no extra bar height.

Trade-off: Wide groups need horizontal scrolling; tiny marks cannot encode large counts reliably.

04 / Window ledger

Title-first workbench

A full-height numeric spine gives the count a real home. The gallery becomes a narrow ledger: numbered windows, small thumbnails, readable names and explicit states.

Why: Best when similar-looking code windows are easier to identify by name.

Trade-off: Less thumbnail detail, more vertical space; longer lists need an explicit scroll budget.

05 / Matrix shelf

Favorite · larger groups

A tiny grid says “collection”; an inline number says exactly how large. A two-row contact sheet makes six windows visible without an extra-wide flyout.

Why: Bounded width and predictable scanning for window-heavy apps.

Trade-off: Small thumbnails and titles; beyond six, use scrolling rather than shrinking cards further.

06 / Focus ticket

Active window leads

A tab-shaped tile carries a small count ticket. The gallery repeats that tab at its crown and gives the active window a generous preview beside two smaller siblings.

Why: Recognize current work immediately while keeping alternatives in view.

Trade-off: Unequal previews; active-first reordering could disrupt spatial memory in a real implementation.

07 / Staggered deck

Expressive alternative

Overlapping window outlines replace the app icon as the group cue. The gallery unfolds into a stepped deck, with the active card slightly raised—depth without hiding other windows.

Why: Most characterful direction, yet still dark slate, fine borders and pale-blue state cues.

Trade-off: Irregular upper edge is busier; generic group glyph sacrifices immediate app-icon recognition.

Pick 01 for familiarity. 03 for rhythm. 05 for scale.

Layered folio is the strongest default: a clear group cue without changing the shell’s character. Window ribbon is the cleanest compact alternative. Matrix shelf wins for larger groups. Keep 02 as a two-window specialist, 04 for title-led work, 06 for active-first recognition, and 07 as the expressive experiment.
