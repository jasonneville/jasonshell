## Decisions and non-negotiable invariants

1. **Only Settings initiates a graceful exit**. A local `Exit JasonShell` button opens a cancel-first modal; opening, Escape, and Cancel do not call native exit, save, hide, or discard. Confirm invokes exactly one path-free `request_shell_exit()`; in failure/fenced state Settings alone offers `retry_shell_exit()` and `cancel_shell_exit()` only **before** any destructive step. After a cleanup step starts, Cancel is unavailable: retry remains available, and a separate explicit recovery/restart outside this feature is not a success path. No renderer PID, HWND, target label, process list, or cleanup selection is accepted.
2. `RunEvent::ExitRequested { api, .. }` calls `api.prevent_exit()` synchronously for every preventable request unless the coordinator is in `ReadyToExit` with its one-shot native final-exit permit. Destructive cleanup is never performed in that callback. Tauri 2.10.3's `prevent_exit` does not intercept the framework's special restart exit code; OS kill/crash remains outside the protocol. `RunEvent::Exit` is observation only. Bar `WindowEvent::CloseRequested` is routed through the same guarded confirmation path and cannot directly call `app.exit` or AppBar cleanup. `Destroyed` is not preventable: retire the instance and report the lost owner; it is not permission to bypass the guard.
3. **No teardown before a clean unanimous, revision-locked freeze.** Snapshot includes every mounted owner regardless of native visibility (hidden Stack popup and retained hidden Settings included). A missing, replaced, unready, busy, invalid, or dirty owner produces a blocking decision; no native cleanup. Expose each blocking owner in Settings as sanitized human guidance and a first-party `Open owner` action if desired; never auto-save or auto-discard. User resolves in its own UI, then starts a new snapshot attempt. An absent owner is not silently assumed clean; a known intentionally unmounted feature is represented by a native `Absent` generation explicitly verified from the host lifecycle, not a renderer assertion.
4. Freeze is **admission**, not visual disabling. Every mutation/save/selection in relevant renderers and native IPC crosses a shared gate; snapshot/revision and freeze must linearize with admission. Outstanding operations have completion receipts; if an operation is pending at snapshot/freeze, reject the attempt rather than waiting indefinitely. Freeze applies atomically across the native owner registry before any side effects; each renderer returns a matching freeze acknowledgement, then coordinator re-reads registration identity/revision and confirms all participants frozen and clean. Any replacement, owner loss, late mutation, invalid reply, event emission failure, or timeout aborts without teardown and thaws still-live owners. After cleanup begins the fence stays set, even on partial failure; Settings stays actionable for retry, not general mutation. Do not unregister the owner on a renderer navigation while allowing cleanup to proceed.
5. Drain **JasonShell-owned** resources only. External Explorer/app task windows, unrelated process-manager targets, independent terminals, and unrelated PIDs are never killed. Complete and verify every mandatory cleanup lane before a single `app.exit(0)` dispatch. Failure retains ownership and completed-step ledger for idempotent retry; never treat a fire-and-forget shutdown or dropping a handle as completion. AppBar restoration is last, but attempt every other independent cleanup lane on the same pass despite a previous failure, collecting sanitized per-lane errors. If AppBar fails, retain its existing merge-back retry state; never final-exit with an active AppBar reservation.

## Exact wire contract (current implementation)

The commands are registered in `main.rs` and exposed only through the existing narrow Settings capability. Current command replies are the Rust `ExitReply` shape:

```ts
type ExitBlocker = { owner: 'settings' | 'theme' | 'stack-editor'; reason: 'dirty' | 'invalid' | 'busy' | 'missing' | 'replaced' | 'unavailable' };
type ExitReply = {
  attemptId: string; state: 'blocked' | 'stopping' | 'failed' | 'exiting';
  phase: 'running' | 'collecting' | 'awaiting-decision' | 'freezing' | 'stopping' | 'failed' | 'ready-to-exit' | 'exiting';
  canCancel: boolean; blockers: ExitBlocker[]; failedSteps: ExitStep[]; completedSteps: ExitStep[];
};
type ExitStep = 'quick-commands' | 'terminal-panel' | 'stack-terminal' | 'speech' | 'snipping' | 'folder-watch' | 'system-info' | 'task-windows' | 'hotkeys' | 'app-bar';
// invoke<ExitReply>('request_shell_exit') — no arguments
// invoke<ExitReply>('retry_shell_exit') — no arguments; only fenced failed state
// invoke<ExitReply>('cancel_shell_exit') — no arguments; only before cleanup is committed
```

`request_shell_exit` and `retry_shell_exit` are async commands returning `Result<ExitReply, String>`; `cancel_shell_exit` and `get_shell_shutdown_status` are synchronous replies. Participant registration/update/unregister and challenge ACK are synchronous commands. Settings control is authorized through the concrete registered Settings instance and lifecycle epoch, not a label, renderer nonce, or PID alone. Retry/status/cancel remain permitted for the registered Settings controller under the recovery fence; non-Windows returns unsupported rather than weakening the ACL.

Events `shell-exit:snapshot`, `shell-exit:freeze`, `shell-exit:thaw`, `shell-exit:status`; emit to the **exact resolved WebviewWindow** via `EventTarget::WebviewWindow { label }` after rechecking native registration identity, not global `emit` or a label-only `emit_to`. Renderer listeners must use current `WebviewWindow.listen` (NOT global `@tauri-apps/api/event.listen`) and bind their handler to the current document's registration nonce. Locked Tauri 2.10.3: `RunEvent::ExitRequested` has an `ExitRequestApi::prevent_exit`; its `listen` default in JS event plugin is any target, so pairing concrete listener target with native emitter target matters (`master_spec.md:236`; local Cargo registry `tauri-2.10.3/src/app.rs:77-91,195-207`, `src/event/mod.rs:25-58`, `src/lib.rs:987-994`). Context7 lookup attempted; quota exhausted, so verify against locked source, not an upgrade.

Use bounded payloads; never emit theme names, draft bytes, paths, HWNDs, process identities or raw errors:

```ts
type Owner = 'settings' | 'theme' | 'stack-editor';
type ExitChallenge = { attemptId: string; registrationId: string; owner: Owner; revision: number };
type ExitSnapshot = ExitChallenge & { kind: 'snapshot' | 'freeze'; clean: boolean; busy: boolean; invalid: boolean };
// Native challenge event: { attemptId, registrationId, owner, revision, phase: 'snapshot' | 'freeze' | 'thaw' }
// reply command `ack_shell_exit_participant({ response })`: response is ExitSnapshot;
// native infers and authenticates caller instance, owner, phase and attempt from registry, never from supplied owner alone.
```

Registration IPC `register_shell_exit_participant({ owner, revision }) -> { registrationId: string }`, `update_shell_exit_participant({ registrationId, revision, clean, busy, invalid }) -> void`, `unregister_shell_exit_participant({ registrationId }) -> void`. Registration ID is native-issued, monotonic, and non-reusable per process (currently represented as a bounded 128-bit-formatted value); associate with native concrete `Caller` (registry HWND/PID/thread/instance) AND document incarnation, owner, revision. Replacing a document increments native epoch and invalidates prior IDs; native owner lifetime is coupled to `on_window_event::Destroyed` and explicit document mount/unmount, not renderer labels. Register one `settings` adapter and one `theme` adapter on the same concrete Settings document; `stack-editor` registers on Stack document even if hidden. A lifecycle declaration of `Absent` is only valid when the host has verified the component never mounted or completed an orderly clean unmount; abrupt unload, crashed renderer, or Destroyed while expected is `Missing`. Require registered owner set for every present document, including the mandatory Settings/theme pair. Set a bounded challenge deadline (e.g. 3 s); timer expiration blocks, never assumes clean. Duplicate/out-of-order/unknown/old-attempt ACKs are rejected without advancing state.

**Concurrency detail:** an untrusted renderer may not create authoritative cleanliness by sending `clean: true`: native controls membership, challenge revision and freeze, while local adapter reports UI facts; a malicious/compromised renderer is outside this UX consistency guarantee. Native save/mutation entrypoints must also validate the fence. A renderer-only gate cannot stop an already admitted async native save; each operation reserves a native in-flight slot before side effects and releases it only after actual completion, with native freeze atomically excluding new reservations. Renderer-owned localStorage mutations (theme and shortcut drafts) must synchronously use an in-document admission guard; instrument all mutation paths and remote theme-preview selection handling, not merely button disabled state. Existing synchronous theme save is blocked once frozen; a native shortcut save/Stack save already underway prevents freezing. Every local keystroke/state mutation increments the per-owner revision immediately, including invalid intermediate hex/alpha input (`ThemeColorField.svelte:14-20,41-51,72-80`), new copy with no edits, name-only edits, pending selection/delete confirmation, shortcut capture begin/end/renew and staged binding, editor load/save/reload/unmount. An unavailable component API or revision overflow is blocking, never wrapped to zero.

**Control Plane theme authority:** a canonical theme-selection request is routed through bounded, correlated request/reply to the already-registered Settings/theme participant. That synchronous, fenced owner alone may persist the canonical selection. The protocol uses native registration identity, request IDs/deadlines, dedupe, and bounded cached unexpired receipts; stale, replaced, expired, unavailable, or frozen authority fails closed, and a foreign document must not write a fallback selection or open a foreign authority window. The authority protocol checks pass 6/6 and the latest three-document browser oracles pass 10/10, including positive persistence, absent-authority rejection, and frozen foreign-writer prevention. This does not establish live Windows acceptance.

## Coordinator and retry seam (current implementation)

`src-tauri/src/graceful_exit.rs` owns the coordinator and injectable `ExitEffects` seam used by focused evidence. The current implementation is summarized below; source remains authoritative:

The implemented `ExitCoordinator` owns concrete `Owner`, `Phase`, `Step`, `ParticipantResponse`, and `ExitEffects` types. It linearizes participant epochs, revisions, in-flight admission, challenge ACKs, completed/failure ledgers, and the one-shot final permit under short-lived locks; IPC, callbacks, worker waits, AppBar work, and UI dispatch run outside the coordinator lock. Collecting accepts one attempt; stale/duplicate/malformed/replaced ACKs fail closed. Snapshot and freeze are checked again immediately before `Stopping`. Cancellation before destructive work thaws participants to `Running`; after stopping begins, the fence and completed ledger remain for retry. `DrainReceipt { finished: true }` is committed only after owned work quiesces. `ExitRequested` consumes the final permit synchronously; `Exit` is observation only.

## Genuine blockers to surface early

- Tauri restart special exit code cannot be prevented by `prevent_exit`; reject/disable direct restart pathways or document an unsatisfied absolute guarantee. Windows force termination, OS shutdown, power loss and process crash also cannot be made graceful by this protocol.
- The isolated fixture does not install or exercise AppBar, hotkeys, task tracking, speech, snipping, or folder-watch runtime lanes; their production completion barriers exist in stable source but remain outside that fixture's runtime certification.
- If the sole Settings renderer dies or native Settings HWND is destroyed after drain failure, in-app retry UI is unavailable; keep retained cleanup state and avoid final exit. This is an availability limitation, not a reason to bypass the fence or force-exit.
