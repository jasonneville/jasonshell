## Production handoff contracts

1. **Stack icons:** new `src/lib/stackIconCache.ts`; Map-like `get`/`has`/`set`/`clear`, scalar `size` and `retainedBytes`. Proposed policy: at most 256 entries and 2 MiB estimated string cost, counting `2 * (normalizedKey.length + (dataUrl?.length ?? 0))`. Null results still charge keys and entry count. Ordinary 32px-ish PNG data URLs vary greatly; the conservative representative fixture uses approximately 8 KiB data URL characters per icon, allowing roughly 127 such retained icons under the byte budget. This is a policy estimate, not measured engine heap. Oversized icons must still display in current folder rows but must not enter cache. Preserve normalized lookup hits and negative-hit behavior; promote LRU only on actual consumption, not incidental queue membership checks. Reject stale job/folder/sequence responses **before** updating cache or diagnostics. Keep current row icons independently owned by `stackState` when cached copies are evicted.
2. **Terminal title metadata:** remove only `TerminalTitleState.recentOutputText`, `rememberTerminalTitleOutput`, and unused output arguments into title building. Runtime `recentOutputText` is still consumed by other features and must remain. Actual helper title output is invariant under varied output text. Mounted early-output-before-start-response path proves 20,000 retained metadata characters before, zero required after, while replay, duplicate suppression, hidden-tab delivery, reattachment, titles, and listener cleanup remain intact.
3. **Process close:** release loaded `processes`, taskbar PID arrays, and kill arming on both local close and accepted hidden `reconcile` transitions; preserve request/generation freshness and pending kill duplicate protection. Keep tab-switch state preservation while still open. Tests include reopening and delayed refresh rejection. Current source already uses `$state.raw`; no reactivity migration is requested.
4. **Git preview:** export `getBoundedStackGitDiffLines(text: string, limit: number): string[]` from existing `src/lib/stackGitPanelState.ts`, wire production viewer to it. Preserve existing empty/trailing-newline semantics, CRLF stripping but lone-CR preservation, exact total line count, localized truncation notice, and unchanged hunk/line classification. Scan/count without materializing all discarded line strings. **Before implementation**, the 30,000-line fixture split 30,000 strings but returned 4,001, and the mounted 10,000-line viewer also split all input. **After implementation**, both use the bounded production scanner without an entire-input split; the retained prefix plus truncation notice remains bounded.
