# Fix Blank Highlighted Search Row on Empty Search Open

## 1. Requirements & Constraints

- **REQ-001**: Opening the centered search panel with an empty query must not show any selected/highlighted result row or blank highlighted row.
- **REQ-002**: Keyboard navigation must still select the first visible result after the user types a query and results are available.
- **REQ-003**: Pressing Enter with an empty query and no selected visible result must not activate any stale or invisible search result.
- **REQ-004**: Existing search panel query ownership must remain in `src/components/TopBar.svelte`; the `search-panel` webview must remain render-only for result rows and row intents.
- **REQ-005**: Existing search IPC command and event names must not change.
- **CON-001**: Do not introduce frontend debounce or backend search behavior changes for this visual-only bug.
- **CON-002**: Preserve unrelated dirty worktree changes.
- **GUD-001**: Use RED-first tests where practical.
- **PAT-001**: Follow existing search source-contract test style in `tests/searchPanelState.test.mjs`, `tests/centeredSearchSurface.test.mjs`, and `tests/searchCloseReset.test.mjs`.

## 3. Alternatives

- **ALT-001**: Fix only CSS for `.empty-state` or `.result-selected`. Rejected unless Phase 1 proves the issue is purely CSS, because it may leave invalid selection semantics and Enter activation risk.
- **ALT-002**: Clear all search panel state on every open. Rejected because it risks breaking existing stale-gated progressive search behavior and same-query retry behavior.
- **ALT-003**: Add debounce or backend search changes. Rejected because the task is a visual empty-state bug and backend behavior is out of scope.

## 7. Risks & Assumptions

- **RISK-001**: Changing `selectedIndex` from `0` to `-1` for empty results could break tests or code assuming non-negative selection. Mitigation: update selection helpers and tests to explicitly cover zero-result and non-empty-result cases.
- **RISK-002**: A CSS-only fix could hide the symptom while leaving stale activation possible. Mitigation: include Enter/activation guard coverage for no visible selected result.
- **RISK-003**: Search panel fallback polling could reapply an older payload with stale results. Mitigation: preserve existing sequence gates in `src/lib/searchPanelState.ts` and add tests using empty current payload after prior non-empty payload.
- **ASSUMPTION-001**: The blank highlighted row is caused by empty-result selected-index/render state, not backend search results. Verify in Phase 1 by inspecting current payload and render conditions.
- **ASSUMPTION-002**: `pnpm build` is the authoritative build validation command from task context. Verify by checking `package.json` if command fails unexpectedly.
