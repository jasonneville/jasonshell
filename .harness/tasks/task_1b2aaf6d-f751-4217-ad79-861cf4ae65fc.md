# Remove Duplicate Overview Section from Task Detail Pane

## 1. Requirements & Constraints

- **REQ-001**: Remove the visible `"Overview"` section from the task detail pane UI.
- **REQ-002**: Preserve the task implementation plan display and all task planning data.
- **REQ-003**: Do not remove or mutate backend task fields such as `spec.problem`, `spec.desiredOutcome`, `spec.scope`, `spec.acceptanceCriteria`, `steps`, or implementation-plan content unless discovery proves they exist only for the removed UI section.
- **REQ-004**: If the task detail pane is not implemented in this repository, stop after discovery and report the owning repository/package.
- **CON-001**: Planning only; do not edit files during planning.
- **CON-002**: Use `pnpm build` as the required project validation command.
- **GUD-001**: Prefer RED-first test coverage before removing UI code.
- **PAT-001**: Preserve unrelated dirty worktree changes.

## 3. Alternatives

- **ALT-001**: Keep the Overview section and rename it. Rejected because the requested outcome is removal, and renaming would preserve duplicate plan-like content.
- **ALT-002**: Remove backend planning/spec fields that feed the Overview section. Rejected because those fields may be used by planning, automation, API responses, or tests; the requirement targets the UI section only.
- **ALT-003**: Hide the Overview section with CSS. Rejected because hidden dead markup is harder to maintain and can still affect accessibility/query tests.
- **ALT-004**: Merge Overview content into the plan section. Rejected unless discovery proves unique non-duplicated information would otherwise be lost.
