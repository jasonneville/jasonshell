# Preserve Terminal Panel Size Across Reopen

## 1. Requirements & Constraints

- **REQ-001**: Reopening the `terminal-panel` must restore the same horizontal and vertical space it had when last hidden/closed during the same app session.
- **REQ-002**: User-resized terminal panel width must not be reset to `TERMINAL_PANEL_WIDTH_LOGICAL` on `show_terminal_panel`.
- **REQ-003**: User-resized terminal panel height must be preserved when reopening.
- **REQ-004**: Restored terminal panel size must remain clamped inside the top-bar host/screen bounds where current positioning logic already clamps width.
- **REQ-005**: After reopen, xterm panes must still run visible fit/resize logic so PTY geometry matches the restored panel size.
- **CON-001**: Planning only; implementer must edit files, not this planner.
- **CON-002**: Preserve unrelated dirty worktree changes.
- **CON-003**: Primary validation command is `pnpm build`.
- **PAT-001**: Follow existing terminal-panel ownership in `src-tauri/src/terminal_panel.rs`, `src/components/TerminalPanelSurface.svelte`, and `tests/persistentTerminalPanel.test.mjs`.
- **PAT-002**: Use focused RED-first regression tests before implementation.

## 3. Alternatives

- **ALT-001**: Persist terminal panel size to `jasonshell-settings-v1.json`. Rejected for this bug unless product explicitly requires restoration across app restart; current terminal-panel runtime policy is non-restoring across app restart.
- **ALT-002**: Remove `panel.set_size(...)` from `show_terminal_panel` entirely. Rejected because first-open/default sizing and host-edge width clamping still need deterministic behavior.
- **ALT-003**: Store size in frontend `localStorage`. Rejected because the native Rust command is the code currently forcing width and already has direct access to native `outer_size()`.

## 7. Risks & Assumptions

- **RISK-001**: Restoring a very large width could place the panel off-screen. Mitigation: clamp restored width with existing `terminal_panel_width_inside_host` and anchor using the final restored width.
- **RISK-002**: Stored height could exceed visible monitor/work area after display changes. Mitigation: minimum clamp is mandatory; implementer should add monitor/work-area max-height clamp if available through current Tauri APIs during implementation discovery.
- **RISK-003**: Fitting xterm before native resize settles could send stale PTY geometry. Mitigation: preserve existing `terminal-panel:open` delayed fit retry and `resizeAllVisiblePanes()` behavior.
- **ASSUMPTION-001**: “Closed” means hidden/reopened during the same JasonShell app session. Verify with product owner before adding settings-file persistence across full app restart.
- **ASSUMPTION-002**: Terminal panel has no native decorations, so the normal close path is `hide_terminal_panel`. Verify no alternate close handler bypasses `hide_terminal_panel`.
