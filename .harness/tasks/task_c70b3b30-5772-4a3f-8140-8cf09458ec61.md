# Terminal Panel Open Auto-Scroll Implementation Plan

## Goal / Problem / Current Context

The persistent JasonShell terminal panel can receive a large amount of PTY output while the `terminal-panel` webview is hidden. When the user opens the terminal again, the visible xterm viewport may not jump to the newest output quickly enough.

Relevant verified files:

- Main terminal UI: `src/components/TerminalPanelSurface.svelte`
- Terminal styles: `src/components/TerminalPanelSurface.css`
- Source-inspection tests: `tests/persistentTerminalPanel.test.mjs`
- Terminal open backend event: `src-tauri/src/terminal_panel.rs`
- Terminal open event constants:
  - frontend: `TERMINAL_PANEL_OPEN_EVENT = 'terminal-panel:open'`
  - backend: `TERMINAL_PANEL_OPEN_EVENT: &str = "terminal-panel:open"`
- Existing policy doc: `docs/terminal-panel-prewarm-idle-policy.md`
- Durable spec: `master_spec.md`
- Changelog policy: `CHANGELOG_POLICY.md`
- Changelog: `changelog.md`

Important current behavior in `TerminalPanelSurface.svelte`:

- `handlePanelOpen()` handles `terminal-panel:open` and window focus.
- `handlePanelOpen()` already:
  - cancels idle prewarm
  - starts terminal on first open
  - ensures xterm views for pane runtimes
  - replays retained session output
  - schedules fit after panel open
- `scheduleFitAfterPanelOpen()` currently focuses xterm, runs `resizeAllVisiblePanes()`, then schedules fit immediately and after `60ms`.
- `writeTerminalOutputForRuntime()` writes PTY output to xterm but intentionally does not force `scrollToBottom()`.
- `tests/persistentTerminalPanel.test.mjs` has an explicit guard that full-screen TUI redraws must not be followed by forced scroll pinning inside `writeTerminalOutput`.

## Behavioral Requirement

When the terminal panel is opened or refocused after hidden/background output has accumulated, all visible terminal panes should quickly scroll to the newest terminal output.

This must happen as an open/focus recovery behavior only. Normal live PTY output writes must continue to avoid unconditional scroll pinning, so full-screen TUIs and cursor-addressing apps remain safe.

## Non-Goals and Side-Effect Warnings

- Do not add `terminal.scrollToBottom()` directly inside `writeTerminalOutput()` or `writeTerminalOutputForRuntime()`.
- Do not force-scroll after every PTY output chunk.
- Do not change ConPTY/session lifecycle, backend terminal session retention, or hidden idle prewarm timing.
- Do not persist terminal scrollback, output, or pane state to disk.
- Do not reduce `scrollback: 8000`.
- Do not alter xterm `convertEol`, `windowsPty`, shell-integration parser, command marks, Quick Select, paste/copy handling, or resize-before-input behavior.
- Do not move terminal ownership back into `StackPopupSurface.svelte`.
- Avoid CSS overflow changes unless inspection proves CSS is the direct cause.

## Phase 2 — Implement Open/Focus-Time Bottom Scroll in TerminalPanelSurface

### Implementation Tasks

1. Edit `src/components/TerminalPanelSurface.svelte`.
2. Add a small open-time helper that scrolls visible xterm panes to bottom after panel open and after replay/fit settles.

Recommended implementation shape:

```ts
function scrollVisibleTerminalsToBottom() {
  for (const runtime of paneRuntimes.values()) {
    runtime.terminal?.scrollToBottom();
  }
  terminal?.scrollToBottom();
}

function scheduleScrollVisibleTerminalsToBottomAfterOpen() {
  window.requestAnimationFrame(() => {
    scrollVisibleTerminalsToBottom();
    window.setTimeout(() => scrollVisibleTerminalsToBottom(), 60);
  });
}
```

3. Wire it from `handlePanelOpen()` and/or `scheduleFitAfterPanelOpen()`.

Preferred placement:

- In `handlePanelOpen()`, after:
  - `ensureTerminalViewForPane(runtime)`
  - `replayTerminalSessionOutput(runtime)`
- Also after `resizeAllVisiblePanes()` completes in `scheduleFitAfterPanelOpen()`, so the viewport lands at the bottom after the fit geometry is stable.

Example intended sequence:

1. `handlePanelOpen()`
2. Ensure terminal panes exist.
3. Replay retained output.
4. Schedule fit.
5. Schedule bottom scroll via `requestAnimationFrame`.
6. Retry once after the existing `60ms` fit retry.

4. Ensure this covers split panes:
   - iterate `paneRuntimes.values()`
   - do not only scroll the active pane unless manual testing proves active-only is desired
5. Ensure this covers the current legacy/global `terminal` reference only if still needed for the primary pane compatibility path.
6. Keep helper idempotent and safe when no terminal exists.

### Tests to Write / Run

- Type/build:

## Risks / Open Questions

- xterm may need the scroll call after `FitAddon.fit()` rather than before it; use `requestAnimationFrame` plus one short delayed retry to avoid geometry races.
- If the panel is hidden but the webview/xterm continues receiving output, replay may not run; open-time scroll must not depend only on replay.
- Existing tests are mostly source-inspection style, so manual smoke is important for actual xterm behavior.
- If `scrollToBottom()` after open disrupts a full-screen TUI already running in an alternate screen, consider guarding with xterm buffer state if available, but do not over-engineer unless manual smoke shows a real issue.
