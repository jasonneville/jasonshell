# Add Worktree Branch Fields to Task Creation and Task Detail Pane

## 1. Requirements & Constraints

- **REQ-001**: Add a user-editable target branch field to task creation.
- **REQ-002**: Add a source branch dropdown to task creation.
- **REQ-003**: Populate source branch dropdown from current local Git branches for the repository.
- **REQ-004**: Display and edit the same target branch and source branch fields in the task detail pane.
- **REQ-005**: Persist both values with the task for future worktree automation.
- **REQ-006**: Do not create worktrees in this change.
- **REQ-007**: Preserve existing task creation and task detail behavior.
- **CON-001**: Planning only; implementation agent must inspect exact task UI/data ownership before editing because known app paths were not provided.
- **CON-002**: Use existing package scripts; primary validation command is `pnpm build`.
- **GUD-001**: Follow RED-first testing where practical.
- **PAT-001**: Follow existing Svelte 5 and Tauri command patterns in this repository.
- **PAT-002**: Reuse existing Git branch listing patterns where possible, especially `src-tauri/src/stack_popup/git_status.rs` and frontend patterns in `src/components/StackPopupSurface.svelte`.

## 3. Alternatives

- **ALT-001**: Store branch metadata inside task description text. Rejected because it is not structured, not reliably editable, and not suitable for future worktree automation.
- **ALT-002**: Create worktrees immediately during task creation. Rejected because the requested scope says values will be used later for automatic worktree creation.
- **ALT-003**: Use free-text source branch input. Rejected because the requested source branch control is a dropdown of current Git branches.
- **ALT-004**: Hard-code common source branches such as `main` and `master`. Rejected because the dropdown must reflect current local Git branches.

## 7. Risks & Assumptions

- **RISK-001**: Task UI may be outside this repository. Mitigation: TASK-001 must identify exact ownership before edits.
- **RISK-002**: Existing Git branch command may require a folder path while task creation may not have one. Mitigation: determine repository root source during TASK-003; add task-specific command only if required.
- **RISK-003**: Existing task persistence may reject unknown fields. Mitigation: update canonical schema/DTO before UI payload changes.
- **RISK-004**: Branch names can contain characters unsafe for future shell commands. Mitigation: store as data only in this change and reject ASCII control characters; future worktree task must use fixed argv, never shell interpolation.
- **ASSUMPTION-001**: The repository root `c:\dev\jasonshell` is the intended Git repo for source branch listing. Verify in TASK-003.
- **ASSUMPTION-002**: The correct field names are `branchName` and `sourceBranch`. If existing code has naming conventions such as `worktreeBranchName`, use the existing convention and preserve equivalent semantics.
