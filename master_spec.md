## Purpose

This spec records current architecture, behavior, limits, safety contracts, validation gaps, and lookup pointers. It is not a changelog and does not store per-request history. Use `CHANGELOG_POLICY.md` for history rules.

## Current product boundary

JasonShell is a Windows shell prototype built with Tauri 2, Svelte 5, TypeScript, Rust, and Win32. It runs as shell-adjacent native surfaces, not as a normal app window.

Current runtime target:

- Windows
- primary-monitor AppBar work-area reservation for top and bottom bars
- Tauri frontend windows/webviews backed by Rust/Win32 integration
- Node contract tests plus Rust tests as automated evidence

Current shipped surfaces:

- top and bottom bars
- Quick Launch
- task tiles, grouping, galleries, and previews
- Stack Browser and Stack text editor experiments
- persistent terminal panel
- Quick Commands and command panel
- centered search
- process manager
- audio, calendar, settings, tray, and related panels
- speech capture uses a dedicated transparent, noninteractive `speech-indicator` surface visible only during recording: a centered, fixed 40×40px opaque circle with a local native-WebGL Rare UI Fluid Orb adaptation and the original 24px mic SVG alpha mask. Cool alloy paint progresses from navy above to silver below; the normalized meter level moves the silver boundary upward as voice grows louder and downward as it softens. The surface maps raw meter level to visual fill with `min(1, level / 0.5)` before smoothing: raw 0.25 targets half fill and raw 0.5 or higher targets full fill. This doubles presentation sensitivity without changing speech detection or the generic smoother. Presentation-only quadratic ease-out interpolates from displayed fill with a 100ms rise and gentler 180ms fall, reaching the exact bounded target; identical targets, including saturated targets, do not restart easing. Meter snapshots, the 0.035 threshold and 300ms word-gap hold remain unchanged: quiet/invalid packets retain the last audible target, then expiry starts the eased release to zero. Terminal status and new nonces reset both meter and displayed fill immediately; stale nonces are ignored. Reduced motion snaps to the current target, hidden documents stop interpolation and resume from displayed fill, and settled fill schedules no frames; presentation listeners/frames are cleaned up on unmount. Mid-level matches the selected navy/silver palette; an internal 0.5px SVG keyline derived from the same artwork preserves full-fill readability without shadows or a backing disk. There is no volume-detected outer ring, glow, waveform, pulse, or geometry change. The exterior remains transparent. Ambient selected-theme-accent/white drift is independent of voice; the renderer resolves the root `--js-color-accent` initially and observes applied theme changes, redrawing paused and reduced-motion stills without starting extra animation chains. Unavailable, failed, or lost WebGL retains an opaque solid fallback using the same theme accent and original alloy ink/internal keyline. Existing shell theme synchronization supplies cross-surface updates; no new theme IPC is used. Animation pauses outside recording and when the document is hidden; reduced-motion changes select a still frame. Forced colors hide decoration and render a CanvasText mic with a static system-color accessibility outline, never a volume highlight. Renderer listeners, theme observer, animation frames, shaders, program, and buffer are cleaned up on unmount. Its nonce-tagged `speech:voice-level` event carries only a normalized scalar meter, never audio or transcript data
- screen snipping uses scoped native overlay and preview surfaces; its native Windows journey remains pending/unverified

Intentional limits:

- multi-monitor support is planning-only until source/tests and live smoke prove implementation
- workspace restoration is reserved and not implemented
- workspace startup commands are not executed automatically
- automation forwarding is planned and not wired
- screen snipping does not provide annotations, spanning mode, autosave, capture history, or upload
- docs must not turn a plan, audit, or archived statement into current behavior

## Architecture map

### Frontend

`src/App.svelte` hosts surface selection and window-level composition. `src/components/` owns rendered Svelte surfaces. `src/lib/` owns state, view models, IPC wrappers, feature contracts, and pure logic. `src/ipc/` owns command/event names and runtime bridge helpers.

Feature clusters:

- top bar: `src/components/TopBar.svelte`, `src/lib/topBarPins.ts`, `src/features/top-bar/`
- top-bar controls: terminal, Quick Commands, tray, speech/mic, and audio reorder horizontally by captured pointer drag after a 4px threshold; order persists in renderer `localStorage`, safely reconciles malformed/stale/duplicate IDs to the five known controls, and excludes time/calendar and search. Clicks below threshold retain existing panel/mic behavior; completed drags suppress the generated click. `src/lib/topBarControls.ts` owns pure ordering/reconciliation logic and `tests/topBarControlReorder.test.mjs` covers it plus Svelte wiring.
- taskbar and previews: `src/lib/taskbar*.ts`, `TaskPreviewSurface.svelte`, `TaskGallerySurface.svelte`
- Stack Browser/editor: `src/lib/stack*.ts`, `src/components/Stack*.svelte`
- terminal: `src/lib/terminalPanel.ts`, `persistentTerminal.ts`, terminal components
- search: `src/lib/search*.ts`, `SearchPanelSurface.svelte`
- settings/tray/audio/calendar/process manager: matching `src/lib/*` and `src/components/*Surface.svelte`
- snipping: `src/lib/snipping.ts`, `src/lib/shellSurface.ts`, `src/lib/surfaceLoader.ts`, `src/lib/topBarControls.ts`, `SnipOverlaySurface.svelte`, `SnipPreviewSurface.svelte`

### Stack Browser Git status refresh

Stack Browser maintains a current-repository identity snapshot for Git status. The context contract returns the verified `repositoryRoot`, `gitDir`, and canonical path; destination badges are rendered only after the current folder passes that context check, so lexical subfolder ancestry is not treated as repository identity. Ordinary navigation within the same repository reuses the lightweight summary without starting another summary or enrichment scan. The summary contract is `StackGitStatus`-compatible for branch, porcelain counts, and badge paths, but excludes line statistics, untracked-content enrichment, remote URL, and ahead/behind data. Remote URL and ahead/behind values are fetched separately through deferred metadata. The existing full `get_stack_git_status` workbench contract and its enrichment behavior remain unchanged.

Explicit **Refresh** and successful local Git mutations, including editor saves, invalidate the repository snapshot. A locally successful commit still invalidates it when a follow-up push fails. Refresh generations and revisions reject stale context, summary, and metadata results. Failed summary or metadata refreshes retain the last good snapshot; a failed context resolution retires the repository identity. This contract adds no polling, persistence, or dependency and does not change the workbench enrichment path.

While the Stack Browser popup is actually visible, including when unfocused, an event-driven native folder watcher refreshes external changes. For a repository it watches the canonical worktree recursively plus the canonical Git directory and actual common metadata directory, with at most three notification roots; this includes working-tree and repository metadata changes outside the shown subfolder. A non-repository folder watches the current folder without inventing repository roots. The watcher uses Windows `ReadDirectoryChangesW`, not interval Git polling, and has no new dependency or persistence.

Native `start_stack_folder_watch({ path })` returns a renderer-free watch token and canonical path; `stop_stack_folder_watch({ watchId })` retires only the matching subscription. Popup-targeted `stack-popup:folder-changed` and `stack-popup:folder-watch-error` events carry the watch token, with path-free error text. Renderer token, context, generation, revision, load, visibility, and disposal guards reject stale events and results. Changes are debounced and coalesced; refresh work is single-flight with one dirty follow-up. Folder rows are committed in place, while Git summary invalidation follows repository changes. Drafts, viewport, search, selection, and focus are preserved, including an unsaved editor draft.

Hide, close, unmount, and popup destruction retire the watcher; reopening starts a new subscription and performs a catch-up refresh. Watch or refresh failures expose a truthful diagnostic and manual **Refresh** fallback while retaining the last good snapshot where available. Linked worktree/common metadata roots are derived from canonical Git identity, and junction subtrees are not traversed into unrelated roots.

### Centered search scope picker

Centered search has an inline shared MeltSelect scope picker with a rounded HTML popup: All, Apps, Windows, Settings, Folders, Commands, and Everything. It filters only the supplied renderer result set (Everything matches `providerId: everything`); it does not expand provider queries or persist scope. Scope survives query/payload refreshes while mounted. Filtering preserves original row identities and result indices; navigation, activation, and folder pinning use only visible rows, falling back to the first visible row when the supplied selection is hidden. An empty scoped set cannot forward activation-producing Enter. The anchored presentation remains unfiltered and retains its existing header.

The centered scope trigger includes the decorative lens in one 112px clickable capsule; its popup spans that entire capsule and shares the search field's small corner radius. Search opts out of MeltSelect's redundant generic close-focus restoration so Tab and outside clicks retain their intended destination; the Select builder still restores the trigger after selection or Escape. Other MeltSelect consumers retain the default restoration policy.

### Process Manager System Info

The Process Manager has exactly two tabs, **Processes** and **System Info**. Opening it selects Processes. Tab changes use a monotonic open generation and tab revision; stale tab responses, snapshots, and native work are rejected. The renderer preserves the process filter, sort, expanded groups, and viewport when switching tabs. There is no added launcher, icon, or window: System Info is a panel in the existing Process Manager surface.

System Info uses versioned, cache-only IPC reads. A native runtime owns independent lanes: live readings refresh every 2 seconds, selected-drive storage every 15 seconds, and hardware inventory every 60 seconds. The renderer polls the current cache every 2 seconds while the visible, focused System Info tab is active; an IPC read never schedules native collection. Native admission and publication require the current visible/focused registered Process Manager instance, matching open generation and tab revision, and the narrow registered-instance ACL. Closing, hiding, losing focus, changing tabs, or opening a new generation invalidates the cache and retires stale work. Close publication carries the retired context (`{ context: retiredContext }`), and renderer monotonic guards reject a stale generation-1 close after a generation-2 open.

The five rendered sections are Overview, Storage, Sensors, Network, and Hardware. Overview reports whole-machine CPU, memory, uptime, and per-adapter GPU readings independently of process filtering. CPU is unavailable when Windows exposes multiple processor groups or more than 64 logical processors because `GetSystemTimes` cannot support a truthful whole-machine value there. GPU utilization selects the busiest physical adapter engine; it is not an adapter-total or process-row sum. Dedicated VRAM is the DXGI dedicated-memory total and excludes UMA shared memory.

Storage reports filesystem, **Caller-visible capacity (quota-aware)**, and total free space separately; the quota-aware capacity is not a claim about physical or volume capacity. Native probes are restricted to selected local roots, with at most 32 enumerated roots and two concurrent registered probe slots. Each same-executable helper has a 1,500 ms deadline and bounded output. A timed-out or cancelled child is killed and waited/reaped before its slot is released; if Windows cannot reap it, ownership and the slot remain retained rather than being falsely freed.

Sensors do not launch or install a provider. CPU and GPU temperature are unavailable with `provider_not_verified` unless a supported already-running provider is verified; unavailable is not zero. Network reports local addresses, gateways, DNS, link speed, and receive/transmit rates per adapter. It does not publish a misleading machine-wide traffic total. Hardware is an allowlist of CPU/GPU names, physical/logical counts, installed RAM, Windows-reported version, and SMBIOS board/BIOS vendor/version. Serial numbers, MAC addresses, UUIDs, asset tags, and keys are not read or returned. There are no battery metrics, history, charts, or System Info actions.

Focused coverage includes operational child cleanup, cache/schema, and registered-instance ACL acceptance. Reproduce the production-mounted mocked-IPC System Info journey with `pwsh -NoProfile -File tests/browser/system-info/run-visible.ps1 -WmuxProcessId <current wmux PID>`. This covers mocked IPC, fixture navigation/modality events, and trusted CDP observation only, not native hardware/HWND runtime or live shell behavior. Dated historical counts are retained in `docs/weekly-health-remediation-2026-11-16.md`; rerun the package gates for current status. Live shell smoke remains consent-gated.

### Custom theme collections and editor

Settings → Appearance mounts `ThemeEditor.svelte`. Built-in themes and generated palettes are immutable. The editor creates a named custom copy from the selected built-in or saved theme, or edits/duplicates a saved custom theme. Renaming is a `Theme name` edit saved with the theme; deletion is confirmed and selecting the active theme for deletion falls back to `base-dark`.

The draft exposes core color fields plus an **Advanced colors & tints** group. Values are validated against the bounded palette token set and deliberately small color grammar; hexadecimal picker values support alpha. Linked aliases remain linked until overridden. Alias expansion is memoized and bounded to 4,096 characters per resolved token before materialization. Composite shadow/focus/inset fields support independently editable tint layers while retaining preset-owned geometry; an individual reset restores that layer's exact raw baseline without resetting neighboring layers. Contrast guidance reports non-blocking estimated ratios, including a warning when a transparent desktop backdrop prevents certification; it does not claim native translucency equivalence.

`themePreview.ts` broadcasts a version-1 preview session across renderer documents. Draft changes apply immediately across the shell, while the saved selection remains authoritative. Hiding Settings retains the draft; Cancel/dispose ends the session and restores the saved theme. Selection from another document is coordinated with the editor and can require discard confirmation. **Save & apply** persists the custom theme and selected ID before ending the preview; failed persistence retains the draft and preview. Reset colors restores `startingPalette`, the source-copy baseline, rather than presentation defaults. There is no terminal palette/import/export contract.

`themePersistence.ts` owns the canonical `jasonshell.themes.v1` local-storage envelope: version 1, collection revision, selected ID, and custom themes. It limits the collection to 100 themes and serialized data to 512 KiB; custom names are 1–80 characters. A successful save publishes the collection and selection together in one canonical envelope write, but this is not a transaction or multiwriter serialization guarantee. Revision checks detect already-changed or deleted records and reject stale writes/deletes with explicit errors; simultaneous renderer writes can still race. The legacy `jasonshell.theme` ID is retained as a compatibility mirror/read fallback, while the canonical envelope wins when present. Loading never rewrites malformed, oversized, or unsupported future-schema data; future versions become read-only. Preferences and the saved theme collection remain the persistence authority; no runtime dependency is added.

The Control Plane's canonical theme-selection request/reply path is owned by the already-registered Settings/theme participant. That owner is the only authority permitted to persist the canonical selection; unavailable or replaced Settings authority fails closed, and a foreign document cannot write a fallback selection. Live Windows acceptance remains a separate consent-gated evidence boundary.

### Settings-only graceful exit

Settings is the sole graceful-exit controller. **Exit JasonShell** opens a cancel-first confirmation warning that unsaved work will be lost. Opening the confirmation, Escape, and Cancel are benign: they do not save, discard, hide Settings, start cleanup, or admit final exit. Confirm sends the path-free `request_shell_exit` once and displays **Exiting JasonShell**; after acceptance, no renderer reply is required. Duplicate requests do not reset the native deadline. Existing saves and editing remain intact. There is no draft handshake or recovery screen, and this is not an OS or whole-PC restart operation.

After acceptance, the native JasonShell process exits within three seconds. This hard exit is independent of Tauri and cleanup completion. JasonShell-owned Quick Command job trees are verified when possible; verification may fail without blocking exit, and the kernel kill-on-close fallback is not a verified-drained result. AppBar and Explorer cleanup is best effort and attempted early; it never blocks exit. Only preaccept rejection is reported in the UI; there is no postaccept status, recovery screen, retry, or retained/reportable failure state. No OS power action is performed. Live Windows/AppBar acceptance and target support remain separate evidence boundaries until demonstrated by source/tests and consent-gated smoke.

### Launcher menu focus

Quick Launch Escape dismisses an open action menu before hiding the panel. Keyboard dismissal returns focus to the connected launcher row; opening or accepting a close clears that menu, while a stale close leaves the current one intact. Quick Commands menu Escape returns focus to the live command row without scrolling or hiding the panel.

### Quick Commands completion banners

The canonical native waiter samples command-panel visibility at completion. Successful and failed exits enqueue only after history saves and only if the panel was hidden. Manual stops, launch errors, unknown visibility, and shutdown do not notify. The primary-monitor overlay shows one non-activating banner for six seconds, keeps up to three waiting, drops the oldest waiting entry on overflow, and clears on panel open. The 50-logical-pixel strip places the verdict and its green check or red exclamation after the command label. The circular dismiss control straddles the top-left corner and visually counts down from the render acknowledgement; reduced-motion mode keeps the ring static, and native timing remains authoritative. The overlay has no persisted state. Native presentation plays one best-effort Confirmation Trill per shown banner from `src-tauri/resources/quick-command-complete.wav`.

The dedicated overlay receives only an opaque action ID, saved display label, and outcome. A private IPC channel wakes the overlay to read current state; it cannot subscribe to shell events, read history, or run commands. Native presentation starts its timer and chime only after the renderer acknowledges the current banner. **Dismiss** retires only the current banner; **Open** uses the existing show-only panel path and hands the saved command and run IDs only to the command panel. The panel selects **Previous Runs** and expands and scrolls to the exact retained run after history loads. An unavailable target is reported without substituting another run. Native pointer, focus, DPI placement, and audible playback require separate consent-gated smoke.

### Task preview presentation

Bottom-bar Quick Launch, direct task, grouped task, and Process Manager controls own transparent native-button hit extensions through the 2px bottom inset within their existing horizontal footprints. Visible faces, content, bar height, and anchor/drag measurements remain unchanged; ordinary hover, activation, context-menu, disabled, focus, and reorder behavior use the same native controls and handlers. Task-strip scrolling/horizontal clipping and local group clipping contain the extensions; gaps, outer margins, and unused strip space remain inactive. Cancelling a capsule reorder gesture retains suppression for its trailing pointer click; keyboard activation remains independent and the next fresh pointer press clears that suppression. Paint and activity/overflow cues stay above the inset, and height resizing remains top-edge-only. Chromium fixture coverage under `tests/browser/bottom-bar-insets/` exercises renderer geometry/input with mocked IPC, not native screen-edge/WebView2 delivery; live Windows shell validation remains consent-gated.

The single-window hover preview uses the inset-lens treatment: a theme-token beveled raised frame, softer corners, a recessed bordered thumbnail, and a decorative app icon beside the title/process caption. Blank or failed icons are omitted without affecting the caption or window actions. The existing activation and separate close controls, hover lifetime, gallery nonce handling, captured-image fallback, and unavailable state remain unchanged.

The preview floats 8 logical pixels away from its host edge (scaled and rounded for DPI), above the taskbar or below its host on fallback placement; monitor-edge clamping still takes priority when space is insufficient. Opening a preview no longer paints a seam connector or removes the source tile's top border/bevel. Existing delayed hide and pointer-entry cancellation remain the hover-crossing mechanism.

The native host remains 332×228 logical pixels. `TaskPreviewSurface.css` and `task_preview.rs` share the thumbnail content geometry: 12 logical pixels on the sides and bottom, and 48 on top; the source is aspect-fit inside that frame. The native viewport remains transparent while its inset perimeter stays visible. Browser fixture coverage in `tests/browser/task-preview-inset/` uses the production component/CSS with mocked IPC; it establishes DOM/style geometry, not live DWM compositing. ### Grouped task gallery presentation

Grouped capsules retain the existing single-item flex/cap, app icon, context menu, reorder gestures, and attention/activity cues. Neutral inline counts replace the warning-styled corner badge. Ribbon capsules keep the app icon and title as a standalone vertically centered group, with small decorative lower window marks; Matrix capsules add a collection glyph without replacing app identity. Closed capsules default by count (two/three Ribbon, four or more Matrix); open capsules adopt the nonce-current native layout response. The gallery outer chrome uses the single-preview treatment: 8px rounding with the theme raised bevel. Its transparent undecorated native host is shadow-free, leaving rounded raised chrome CSS-owned and avoiding an extra OS border.

The native `task-gallery:open` payload supplies ordered windows, a session nonce, a monotonic same-session revision, and logical-pixel layout. The renderer honors that layout rather than independently choosing columns. Ribbon fits two or three windows in one row; Matrix uses up to three columns and two visible rows with a stable 12px scrollbar gutter and vertical scrolling beyond. Shared standard geometry is 8px panel inset/gaps, 24px header, 180×136px cards, a card-local thumbnail at (4,4) sized 172×96px, and a 32px footer with a separate 24×24px Close button. Constrained native layouts can reduce width/viewport height without shrinking the Close target. `src/lib/taskGalleryLayout.ts` contains the geometry/types and a fixture/legacy fallback.

Inline preview synchronization sends nonce/revision/strictly advancing request ID, the measured gallery-client viewport, and only fully viewport-contained thumbnail frames (bounded to 12). No card hover/focus request opens a separate preview. Scroll/resize changes clear old destinations and coalesce fresh measurements; partially visible cards retain captured-image/unavailable DOM presentation. Same-session snapshot revisions preserve registrations for unchanged layout/scale/order and surviving window identity/minimized state; removed or changed destinations are retired before host mutation rather than unconditionally clearing the whole set. Renderer retention requires continuity of both HWND and the same positive safe-integer process ID: changed or unknown identity drops cached captures, live markers, and local menu or pending-menu intent. This HWND/PID continuity boundary is not protection against PID reuse; native identity validation remains authoritative. A surviving local right-click menu remains across refresh, while a pending menu open waits for a matching current-revision empty clear acknowledgement before appearing. Context-menu overlays, hidden documents, closure, and disposal clear native destinations so the local menu sits above the webview; genuine captured backups remain visible when capture succeeds, while an actual capture failure remains unavailable. Per-session, revision, geometry, request, and disposal guards reject stale responses; live/captured/unavailable responses never remove windows. Close remains duplicate-guarded and snapshot-authoritative, with visible failure diagnostics.

Keyed cards preserve supplied order and surviving activation/Close DOM focus across layout changes. Hover never selects or steals focus. Only the selected card's activation/Close pair enters the tab sequence; horizontal arrows stay within a row, vertical arrows use authoritative column stride with short-last-row clamping, and Home/End reach the endpoints. Keyboard movement scrolls the selected card into view immediately. Production-mounted mocked IPC coverage is owned by `tests/components/task-gallery-runtime.test.ts` and `tests/browser/task-gallery/`; that evidence is not live DWM, native HWND identity/action, monitor placement, or mixed-DPI certification. Those native journeys remain consent-gated.

`src/components/OverflowTicker.svelte` provides locally clipped text motion for direct task tiles, grouped capsule labels, and individual gallery titles without replacing their buttons or moving icons/counts. Idle titles use a width-bound ellipsis viewport. Hover or focus starts a single 600ms engagement delay; overflowing text travels left at 40 logical pixels/sec to its measured endpoint, holds 2000ms, returns at the same speed, holds at the origin for 3000ms, and repeats without another engagement delay. Either hover or focus keeps the cycle alive; leaving both cancels motion and restores the idle origin. Resize and title changes remeasure; intrinsic fractional bounding-box width avoids rounded `scrollWidth` restarting the animation. Fitting titles and reduced-motion preferences do not animate. Full text remains in the existing accessible label/title contract, with no additional tab stop or gallery selection change.

Ticker acceptance coverage lives in `tests/components/overflow-ticker.test.ts`, including the fractional-width resize-observer regression. Browser probes on the production BottomBar and gallery with mocked native IPC establish natural transforms, endpoint/hold/return timing, focus/hover cancellation, reduced motion, local clipping, stable icons, and 320px reflow. That evidence does not certify native shell behavior, screen-reader output, or forced-colors presentation.

### Grouped taskbar context menu

Bottom-bar gallery capsules (two or more windows) use the same external context-menu overlay and shared menu primitives as standalone task tiles. Their right-click menu exposes Open in Process Manager, Pin to taskbar, and Close all windows; gallery hover/click and drag behavior remain separate. The origin retains an opaque-token-scoped member snapshot; the overlay receives presentation state, not HWNDs or paths. Process and pin prefer the member that was active when the menu opened if it still survives, otherwise the first captured survivor (process lookup requires a valid PID). Selections recheck group membership and HWND/PID against current taskbar state and exclude newly joined windows. Close all rechecks each target, continues after individual failures, and uses the authorized `run_task_window_action` request-only `request-close` route: native identity/PID validation precedes WM_CLOSE dispatch, without termination or elevation fallback. App save prompts can therefore keep windows open. Existing standalone close behavior is unchanged. Rendered mocked-IPC coverage lives in `tests/components/taskbar-group-menu.test.ts`; native source safety contracts live in `tests/taskbarGroupMenuContract.test.mjs`. Live WebView2/native shell verification remains consent-gated.

When the external context-menu overlay is height-constrained, keyboard navigation reveals the focused row by scrolling the menu without moving the surrounding overlay. Dismissing the menu still requests focus restoration; choosing an action does not.

### Terminal panel startup and status presentation

The terminal toolbar wraps when needed to keep actions and keyboard focus visible in a narrow window. Escape from the open Actions or Recent dropdown or its trigger dismisses only that dropdown and returns focus to the trigger if still connected and enabled. Terminal search in both the dedicated panel and Stack has a separate Close terminal search control; it clears the query and refocuses the terminal without closing the session.

The persistent terminal panel keeps hidden mount lazy: it does not eagerly create xterm/ConPTY, and schedules the unchanged bounded `5000 ms` idle prewarm. A panel-open event or terminal-panel focus cancels the pending prewarm and starts or joins the shared startup promise. Existing backend sessions are reattached rather than duplicated; idle prewarm may start/list-attach the backend session without creating xterm. Visible startup still preserves attach/replay, focus, resize-before-input, tab/split, reuse, and cleanup behavior.

Normal startup and output waiting never cover the terminal with a status notice. Genuine failure, exit, and explicit stopped-state diagnostics remain visible and accessible before a pane exists and after output, including startup rejection, PTY/read failure, exit-before-output, later exit, and stopping the final tab. Existing output remains visible alongside a later diagnostic, and retry clears the prior failure without duplicating notices. Rendered coverage is in `tests/components/terminal-panel-status.test.ts`; its mocked IPC/xterm environment is not native ConPTY or desktop Tauri certification. The focused policy and tradeoffs are documented in `docs/terminal-panel-prewarm-idle-policy.md`.

### Runtime memory ownership

Quick Commands renderer transcripts retain the newest 256 rows per run and the newest 20 completed runs alongside known active runs. Native snapshot omission alone does not terminate an active run. Live-known pending input metadata survives transcript-row eviction; terminal status clears it monotonically. Retired history cannot be restored by delayed polls or events. This does not certify recovery of an evicted pending request on a cold renderer mount: native snapshots have no independent pending-request field.

App-index snapshots share immutable `Arc` generations; persisted serialization borrows entries without changing the disk schema. App ranking sorts lightweight candidates with the existing score/title/key ordering before hydrating retained results and icons. Process sorting prepares taskbar PID membership once per invocation, sharing it across refresh ordering passes rather than caching caller options across invocations.

Clipboard preparation releases temporary DIB staging after its owned global-memory copy succeeds and before allocating PNG global memory; conservative admission accounting and publication ownership remain unchanged. Terminal readers move decoded text through the borrowed event emission and into the polling queue without a second text clone. Ordinary ArrayBuffer-backed screenshot subviews preserve offset/length when passed to Blob without a preparatory payload copy; shared backing retains an ordinary-buffer compatibility copy, and Blob still owns a snapshot.

Terminal renderers share one dedupe tracker per panel session rather than copying whole seen-key Sets on each chunk. Exact integer intervals preserve holes, out-of-order chunks, stream/session identity and duplicate suppression; exceptional numeric sequences retain exact fallback membership. Contiguous histories compact, but arbitrarily fragmented histories can still grow. Both renderers poll the existing authorized chunks-only `poll_stack_terminal_session` route through a typed adapter; the legacy aggregate-output read command remains available. Native stop removes session ownership without retaining unused stopped-ID tombstones. These changes do not impose a session quota or remove replay.

Process descendant enrichment reuses count-only traversal scratch while preserving existing cycle/duplicate semantics and leaving termination planning untouched. Speech inference input reserves the required contiguous vector once without changing model lifetime or sample order. PNG CRC uses a fixed 1 KiB table with unchanged encoded bytes.

Stack renderer icon reuse uses an LRU bounded to 256 entries and 2 MiB of estimated key/value string storage, including negative entries. Oversized icons remain displayable without cache admission; stale batches and post-disposal listing continuations cannot populate the cache. This accounting is not a JavaScript heap-size guarantee. Terminal title metadata does not retain unused output copies; runtime output and replay remain separate. Accepted Process Manager hide transitions release process rows and taskbar PID snapshots without clearing pending-kill duplicate protection. Git diff previews scan for the exact total line count while materializing only the displayed prefix and truncation notice.

`docs/performance-memory-lab.md` records isolated allocation/retention evidence and its limits. These fixtures do not establish whole-app private bytes, WebView2 residency, native latency, or live Windows shell acceptance.

### Backend and native

`src-tauri/src/main.rs` registers commands, windows, setup, and plugins. Rust modules own native integration:

- shell windows and work area: `shell_windows.rs`, `appbar.rs`, `layout.rs`
- task windows: `task_windows/`, `task_preview.rs`, `task_gallery.rs`, `taskbar_menu.rs`, `launchers.rs`
- Stack Browser: `stack_popup.rs`, `stack_popup/`
- Stack Browser Open With enumerates Windows-registered association handlers for the selected file extension with `SHAssocEnumHandlers`/`ASSOC_FILTER_NONE`. Each candidate exposes only the handler's native identity, UI label, and `windows-association` provenance; the ID is presentation-only, is not an executable path, and does not imply every installed app or Explorer-identical ordering. Selecting a candidate re-enumerates the current handler identity and invokes it with a Shell `IDataObject`; it does not launch guessed executables, fall back to another handler, write default associations, or persist an app list. The existing **Choose app...** route remains the native picker, including when enumeration is empty. Renderer commands authorize the Stack popup and keep path normalization, directory rejection, association enumeration, and invocation on the blocking worker boundary. ### Speech model installation

Speech model provisioning is a runtime import workflow, not a repository or bootstrap prerequisite. Settings exposes **Import speech model**; the backend opens the picker, accepts only trusted Parakeet TDT 0.6b v2 int8 `.tar`, `.tar.gz`, or `.tgz` archives, validates them in a secure staging area, and requires a successful ONNX model load before replacing the installed model. The three required model files are `encoder-model.int8.onnx`, `decoder_joint-model.int8.onnx`, and `vocab.txt`.

The validated model is installed under the per-user `app_local_data_dir`, becomes available to the current session, and the startup resolver selects the newest valid installed generation after restart or app update without requiring the original archive. Audio and transcripts are not newly persisted by model installation. Installed files may be removed with the app's local data; documentation must not promise survival across uninstall or profile deletion. Archive provenance is guidance only: no pinned hash, license clearance, or independent compatibility claim is established.

Each replacement publishes a unique generation and retains older generations. Repeated imports therefore consume additional disk space, and an interrupted import may leave a staging directory; no power-loss durability guarantee is made.

Its native folder chooser shares archive import admission, busy reservation, epoch invalidation, cancellation, and readiness handling. ### Screen snipping contract

The Windows application builder uses `DeviceEventFilter::Always`: this always filters out Tao raw device events, not ordinary DOM/window input. In the locked Tao 0.34.8 implementation it unregisters raw mouse/keyboard input (`RIDEV_REMOVE`). JasonShell has no raw `DeviceEvent` consumers; the setting preserves the global Escape hook when an owned WebView is focused, addressing the focus-dependent interaction reported in Wry issue #1761. Normal keyboard forwarding, pointer interaction, and nonactivating snipping surfaces remain unchanged. Any future raw-device feature must explicitly revisit this compatibility boundary. The exact Windows interaction and focused-shell acceptance require native regression evidence rather than compile-only certification.

Opt-in snapshot fields `callback_escape_down`, `callback_escape_up`, `callback_tls_missing`, and `callback_owner_missing` are process-total Escape-only boundary counters. Static atomic recording occurs before callback TLS/owner lookup, so native callback arrival can be distinguished from routing-state lookup failure without retaining or dereferencing a diagnostic owner on the callback path. These counters do not establish that Windows will deliver future callbacks.

Temporary Escape diagnostics are default-off. At listener startup only, a regular `snip-escape-diagnostics.enable` file in `%LOCALAPPDATA%\Temp\opencode` enables `snip-escape-diagnostics-{pid}.json` in that directory. A separate weak-owned worker overwrites a scalar-only snapshot (maximum 4 KiB) every 250 ms; callback instrumentation uses fixed atomics only, without logging other keys, text, capture tokens, HWNDs, titles, images or application paths. Counters distinguish Escape edges/repeats even outside selection, hook registration/pump/exit, routing/mailbox/delivery, and coordinator arming/cancellation state. Cross-counter snapshots are approximate, not transactional; file readers must retry transient partial writes. No delivery behavior or latch reset changes. Remove the marker before the next launch to disable; removal does not reconfigure a running listener. Shutdown/drop never joins filesystem work, and output files remain until explicitly deleted. Registration counters/pump ticks do not prove Windows has retained a hook; full-shell failure reproduction remains human-owned.

Escape observed while visible overlays are still pinned for show/armed emission is retained on that exact generation. After those native effects return, arming atomically either publishes armed/unpinned state or retires the cancelled generation before releasing its pin; no second keypress or worker retry is needed. This transient arming pin is distinct from an already-armed completion pin, which continues to win over cancellation.

During Selecting, Escape cancels either entry route before or during dragging without activating an overlay. A runtime-owned passive `WH_KEYBOARD_LL` listener observes down/up events independently of WebView focus; every key is forwarded through `CallNextHookEx`. The dedicated callback thread snapshots a lock-free Selecting generation published under the authoritative coordinator transition lock, deduplicates held-key repeats, and records the latest observed generation in a bounded atomic coalescing mailbox. The single deferred worker receives bounded wakeups, not cancellation payloads: a full wakeup slot cannot discard newer work behind a stale event. Generations are monotonically unique and never reused. Deferred delivery resolves the authoritative token only if the observed generation is still Selecting, then uses the native-only cancellation seam; it cannot retarget a replacement. Release rearms observation; a short press remains deliverable after release without key-state sampling or callback lock contention. Token/Selecting/mutation-pin checks and removal are atomic in the coordinator: stale tokens, key-up, duplicates, Preparing, Preview, Saving, and stopped runtimes are inert; an already-pinned completion wins. Shutdown/drop invalidates queued deliveries and signals the owning thread to unhook; neither thread retains the runtime. Registration failure rejects runtime installation rather than installing a sampling fallback. Cancellation uses normal generation retirement/window disposal and frame release without clipboard/file publication or keyboard suppression. Native cross-window Escape delivery remains consent-gated validation.

Snipping starts only through the exact registered top-bar renderer instance or the trusted native hotkey dispatcher; other panel renderers cannot invoke the start command. The top-bar control deduplicates pending starts, disables itself while preparation is pending, and clears an earlier start error before each attempt; timeout and other rejection messages are sanitized, accessible retry guidance rather than raw IPC errors. Native authorization is concrete-instance based for the caller, each overlay, and the preview; matching labels alone are never authority. Context and armed listeners use the current WebviewWindow label as their listener target, and native emission resolves the exact registry-owned destination and emits to that same WebviewWindow target. This paired scoping is required because Tauri 2.10.3's global `listen` default is any target; an emitter target alone does not prevent cross-WebView delivery. The capture freezes all enumerated monitors before creating overlays. Ordinary JasonShell bars, panels, and tooltips remain included in the pixels; snipping overlays and the retained previous preview are excluded from capture. The first backend-accepted monitor pointer-down binds the generation, and completion crops only that monitor using trusted native geometry/scale.

The native hotkey path snapshots the capture/focus origin on the `WM_HOTKEY` message thread, including a monotonic observer epoch and live HWND/PID/thread identity, before dispatching capture work. A same-process origin must be a supported concrete registered ordinary JasonShell surface; an external app origin is also supported. The dispatcher does not recache a renderer-activated foreground target or use an external-window history for hotkey authorization. Native registration entries carry concrete HWND instance properties and a bound origin generation; retired generations cannot create or publish new native snipping windows, and recycled HWNDs fail the instance check. Coordinator disposal retires pending native generations before closing their windows, while native construction admission rechecks retirement and readiness. During preparation, generation-scoped passive focus-loss holds keep the ordinary shell surface mounted without showing or refocusing a snipping helper. Close cleanup retires the entry immediately and queues destruction without waiting for observer validation on the UI callback. Hotkey feedback is a bounded, monotonic attempt event with sanitized codes; the top bar accepts only validated newer attempts and renders retry guidance.

The current dependency line uses a repository-owned Wry 0.54.4 backport at `src-tauri/vendor/wry/`, selected by `[patch.crates-io]` in `src-tauri/Cargo.toml`. It applies only official upstream PR 1795, commit `3fbf592feab29ffb269778a6f5573746a2f25a4a` ([PR](https://github.com/tauri-apps/wry/pull/1795)): `RemoveWindowSubclass` runs before the boxed controller is dropped, preventing synchronous COM-release reentry through a still-registered callback. Wry's original licenses/notices are retained. Wry 0.56.1 contains the released fix but is outside the current `tauri-runtime-wry ^0.54.0` compatibility line; remove the vendor patch only when a compatible official upgrade replaces it. The actual-source facade's RED ordering cases and current validation boundary are recorded in `tests/snipping-postmerge-crash-evidence.md`; this automated evidence does not prove the native app crash is resolved.

Completion creates a hidden non-activating preview, then attempts the existing automatic native Copy immediately before showing it. Clipboard outcomes remain distinct and truthful: committed, committed-warning, rejected, and publication-unknown. The visible preview persists without activation and places right-aligned icon controls below the image: **Copy**, **Save**, and **Dismiss**. A separate header **Close** control uses **Dismiss** behavior. Save is path-free at the renderer boundary, uses the native PNG picker, pins the generation/image while the picker is open, and publishes through a same-directory sibling/atomic PNG path; cancellation has no file effect. Save and clipboard publication continue to use the existing stored-block `png_rgba` serializer and its exact PNG/golden contract.

The renderer receives bounded binary PNG data and no HWND, path, origin, scale, or display authority. Snipping capabilities are scoped separately to the top bar, overlay, and preview. Authorized image reads may encode concurrently without taking the mutation-busy path; each read owns RAII source and bounded-output reservations that survive cancellation or replacement until its worker releases them, and late results revalidate generation, deadline, and concrete caller before returning bytes. Coordinator admission accounts against the production 512 MiB staging budget for retained source/crop/frozen buffers, active read reservations, and the largest simultaneous capture GDI DIB; this is an admission ledger, not an absolute process or IPC memory cap. For `Coordinator::image` frame/crop responses only, `png_rgba_transport` attempts a lossless filter-0, fixed-Huffman DEFLATE stream using row-local adjacent identical RGBA runs (distance four, lengths four through 256), with no dictionary/workspace or dependency. A preflight rejects non-beneficial or non-repeating inputs before encoding; an unsuccessful or non-smaller attempt clears and reuses the same initially reserved Vec for the unchanged stored fallback. Compact payloads do not imply smaller allocation: the initial capacity remains the stored-PNG size, and the existing logical ceiling, trailing 20-byte reserve, capacity check, and retained-bytes-plus-capacity 512 MiB admission remain in force. Image RAII, source/output reservations, cancellation/stale checks, and concrete-window authorization are unchanged. Before final placement, native overlay creation applies capture exclusion, stages a hidden 1×1 rectangle on the target monitor to settle synchronous mixed-DPI transitions, then applies the authoritative physical monitor rectangle and retains an exact-bounds guard. The shared native WebView builder disables the Windows shadow so undecorated client insets do not reduce overlay client coverage. It preserves nonactivation, authorization, and cleanup behavior. The native helper and runtime use bounded deadlines (including the five-second preparation/readiness bound), monitor/frame/staging budgets, exact token checks, and fail-closed cleanup. These limits do not certify live OS behavior.

Preview context can reach the renderer before hidden-preview completion finishes. For both targeted events and context snapshots, the existing image request verifies the concrete preview, capture token, and monitor, then waits for completion if needed. The bounded wait reserves no image memory; success requires the preview transition and completion pin release. Rollback, native retirement, and shutdown wake the waiter without exposing the pending crop. Overlay image reads and manual Copy/Save admission do not use this readiness wait.

The earlier 2.9× stored-serializer/fallback benchmark does not measure compact transport, native IPC, or end-to-end latency; the two clean-release journeys establish the native journey but do not attribute their timings or payloads to compact transport. Compact-transport latency attribution and payload-size measurement remain unverified.
- The isolated opt-in single-display placement fixture `primary_monitor_visible_overlay_preserves_full_client_coverage_and_nonactivation` exercises the production native window path through visible/show and independent renderer drains, checking full client coverage, capture exclusion, nonactivation, and the active monitor DPI (including the reviewed 288-DPI run). A clean ordinary release executable has now completed two fresh-process `SingleDisplay` journeys with exact overlay/client bounds, protected-bar preservation, real selection, preview, clipboard DIB, and dismissal; this is bounded two-run evidence, not an instant-start or broader performance guarantee. Exact release identity, timings, oracles, command, and cleanup evidence are recorded in `tests/snipping-release-native-e2e.md`. Payload size, pixel equality, consumer paste, work-area restoration, compact-transport latency, and broader repeatability remain unverified. `LegacyDual` remains separately hardware-gated by its strict two-real-monitor precondition. The original `cargo:test` integration launch remains blocked before entry by `0xc0000139` from missing Common Controls v6 resource; its source cause is unresolved and is not evidence of a source or native pass.
